# CStudio 하단 Role Switcher UI 컨셉 v1

## 목적

이 문서는 기존 `고정 셸 + 역할 전환` 설명 문서와 별개로, 사용자가 새로 제안한 방향을 바로 눈으로 판단할 수 있게 만든 UI 컨셉 문서다.

핵심 가정은 다음과 같다.

- 역할마다 독립적인 메인 화면이 있다
- 한 사람이 여러 역할 화면을 오갈 수 있다
- 조직에 따라 특정 역할 화면만 보이거나 잠길 수 있다
- 필요하면 역할 화면을 분리해 멀티 스크린/멀티 윈도우로 볼 수 있다

## 한 줄 요약

`cstudio`의 메인 네비게이션을 하단 `Role Switcher`로 두고, 중앙은 현재 역할의 메인 스크린으로 사용하는 안이다.

즉 이것은 “회전 캐러셀”보다 “하단 전환 바를 가진 멀티 스크린 워크스테이션”에 가깝다.

## 이 그림에서 보아야 할 것

### 1. 하단 Role Switcher

하단 바가 메인 전환 장치다.

- `Author`
- `Analysis`
- `Admin`
- `Ops`

이 각각이 하나의 역할 스크린 진입점이다.

### 2. 중앙은 현재 역할의 메인 스크린

현재 시안에서는 `Pipeline Authoring`이 열려 있다.

즉 가운데는 장면처럼 분명히 달라질 수 있다.

### 3. 좌우 패널은 현재 스크린에 종속

좌우 패널 위치는 유지될 수 있지만, 그 내용은 현재 역할 스크린에 따라 달라진다.

즉 이 안은 “중앙만 바뀌는 구조”보다 더 역할 스크린 중심이다.

### 4. 멀티 윈도우 확장

오른쪽 위의 `Pop-out` 같은 액션은 나중에 다음 확장을 암시한다.

- 현재 역할 스크린을 새 창으로 분리
- 다른 모니터에 별도 배치
- 예: `Author`와 `Analysis`를 동시에 띄우기

## 이 안의 장점

- 사용자가 역할 화면을 “장면”처럼 명확히 인식할 수 있다
- 하단 스위처가 역할 개념을 아주 직접적으로 보여준다
- 한 사용자의 멀티 역할 이동과 역할별 권한 제어를 한 UI에서 함께 다룰 수 있다
- 향후 멀티 윈도우 확장과 잘 맞는다

## 이 안의 중요한 설계 포인트

### 역할은 화면 단위로 다룬다

권한도 패널보다 화면 단위로 걸리는 편이 자연스럽다.

- 보임
- 잠금
- 숨김

이 세 정책을 하단 스위처에서 바로 표현할 수 있다.

### 하단 바는 단순해야 한다

하단 스위처는 툴바가 아니라 역할 전환 바다.

즉 너무 많은 버튼을 넣지 않고 다음 정도가 적절하다.

- 역할 이름
- 현재 활성 강조
- 잠금 표시
- 새 창 분리

### 중앙은 역할별로 충분히 달라질 수 있다

이 안에서는 중앙이 더 강하게 달라도 된다.

- Author는 편집 중심
- Analysis는 비교/리포트 중심
- Admin은 정책/검증 중심
- Ops는 운영 대시보드 중심

즉 사용자는 “지금 어떤 역할 화면에 와 있는지”를 바로 느껴야 한다.

## 현재 시안의 의도

이 문서는 아직 구현 명세가 아니라 판단용 컨셉이다.

즉 지금 단계의 목표는:

- 하단 Role Switcher가 `cstudio`에 맞는지
- 역할 화면을 더 독립적으로 다루는 방식이 맞는지
- 멀티 스크린/새 창 분리 방향이 설득력 있는지

를 눈으로 빠르게 확인하는 것이다.

## 다음 단계

이 안이 맞다면 다음으로 이어질 문서는 아래 둘 중 하나다.

1. `Author / Analysis / Admin / Ops` 각각의 메인 화면 상세 시안
2. 하단 Role Switcher 기반 멀티 윈도우 동작 시퀀스 문서

지금 문서는 우선 “당신이 말한 방향을 실제 화면 아이디어로 옮기면 이런 형태다”를 보여주기 위한 v1이다.
