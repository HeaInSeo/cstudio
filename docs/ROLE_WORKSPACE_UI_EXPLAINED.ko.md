# CStudio 역할 전환 UI 쉽게 보기

## 먼저 한 줄 요약

이 설계는 “화면 전체를 계속 돌려가며 바꾸는 앱”이 아니다.

이 설계는 “하나의 고정된 Rider형 셸 안에서, 역할별 작업공간만 바꾸는 앱”이다.

## 왜 헷갈리는가

문서에 `< >` 버튼과 “좌우 전환”이 나오기 때문에, 겉으로 보면 화면 전체가 통째로 바뀌는 구조처럼 읽힌다.

하지만 실제 의도는 다르다.

- 바뀌지 않는 것: 앱의 바깥 프레임
- 바뀌는 것: 그 프레임 안에 담기는 역할별 작업 내용

즉 `< >`는 “앱 장면 전환 버튼”이 아니라 “역할 워크스페이스 전환 버튼”이다.

## 왼쪽 그림: 처음 제안과 가까운 해석

왼쪽은 사용자가 처음 말한 아이디어에 더 가까운 해석이다.

- `Pipeline`
- `Analysis`
- `Admin`
- `Ops`

이 각각이 거의 독립적인 메인 장면처럼 느껴진다.

이 방식은 전환 감각은 강하다. 하지만 다음 문제가 생긴다.

- Rider 같은 IDE 느낌이 약해질 수 있다
- 역할이 바뀔 때마다 앱을 다시 배우는 느낌이 생길 수 있다
- 권한 제어와 패널 재사용 구조가 더 복잡해질 수 있다

## 오른쪽 그림: 지금 문서가 말하는 방식

오른쪽이 현재 `cstudio` 문서의 실제 의도다.

바깥 셸은 항상 같다.

- 상단 메뉴/타이틀 영역
- 좌측 탐색 위치
- 중앙 문서 호스트
- 우측 속성 위치
- 하단 상태/로그 위치

하지만 그 안의 내용은 현재 역할에 따라 달라진다.

예를 들면:

### `Pipeline Authoring`

- 좌측: 그래프 자산, 노드 팔레트
- 중앙: `DagEdit`
- 우측: 노드/그래프 속성
- 하단: validation/build

### `Pipeline Analysis`

- 좌측: 실행 세션, 리포트
- 중앙: 비교/분석 문서
- 우측: 결과 메타데이터
- 하단: 성능/이벤트 로그

### `Tool Administration`

- 좌측: 도구 목록, 정책, 검증 대기열
- 중앙: 설정/정책 문서
- 우측: 스키마, 권한, 배포 조건
- 하단: validation/register 로그

### `K8s Operations`

- 좌측: cluster/namespace/workload 트리
- 중앙: 운영 대시보드와 리소스 문서
- 우측: 상태/액션/헬스
- 하단: 이벤트/스트림 로그

## 핵심은 무엇이 고정되고 무엇이 바뀌는가

### 고정되는 것

- `cstudio`라는 앱의 외형적 작업 셸
- 패널 배치의 큰 구조
- 사용자가 위치를 인식하는 방식

### 바뀌는 것

- 현재 역할 이름
- 좌측 탐색의 내용
- 중앙 기본 화면
- 우측 속성 패널의 의미
- 하단 로그/진단의 성격

## 이걸 공간 전환처럼 느끼게 할 수는 있나

가능하다. 다만 “앱 전체가 다른 앱처럼 바뀐다”가 아니라 아래 정도가 적절하다.

- 상단의 현재 워크스페이스 이름이 바뀜
- 중앙과 좌우 콘텐츠가 옆으로 슬라이드되듯 교체됨
- 현재 역할 색상이나 배지가 함께 바뀜

즉 감각은 공간 전환과 비슷할 수 있지만, 구조는 IDE형 셸 유지에 더 가깝다.

## 아주 단순한 비유

### 처음 제안의 해석

TV 채널을 돌리면 채널마다 방송국이 완전히 달라 보인다.

### 현재 설계

같은 방송국 스튜디오 안에서 진행 프로그램만 바뀐다.

`cstudio`는 후자에 가깝다.

## 왜 이쪽을 추천했는가

`cstudio`는 앞으로 다음을 한 앱에 담으려 한다.

- 파이프라인 제작
- 분석
- 관리자 authoring
- 운영 관찰

이 기능들은 서로 다르지만, 사용자는 여전히 “같은 워크스테이션 안에서 이동한다”는 감각을 가져야 한다.

그래서 전체를 여러 앱처럼 쪼개기보다, 하나의 강한 셸 위에 역할을 바꾸는 쪽이 장기적으로 더 안정적이다.

## 문서를 읽을 때 이렇게 보면 된다

문서에서 `< >`가 보이면 이렇게 해석하면 된다.

- 잘못된 해석: 화면 전체를 갈아끼우는 버튼
- 의도한 해석: 현재 역할 워크스페이스를 바꾸는 버튼

문서에서 “회전”이 보이면 이렇게 해석하면 된다.

- 잘못된 해석: 완전히 다른 앱 화면으로 점프
- 의도한 해석: 같은 셸 안에서 다른 역할 문맥으로 이동
